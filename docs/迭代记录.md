# 迭代记录

> 每次改动记录：发现了什么问题 → 判断原因 → 怎么改 → 效果。面试时「遇到过什么问题、怎么解决的」就从这里讲。

## v0.1（2026-11-18）第一版跑通

**功能**：模糊需求输入 → 多轮追问（≤6 轮，带快捷选项，可随时跳过）→ 实时生成结构化需求单 → 分单判断（AI 直接做 / 人机协作 / 交给真人）→ AI 初稿 → 复制需求单 / 导出对话记录。
**模型**：通义千问 qwen-plus（百炼），单轮延迟约 4.5–6.5 秒，单轮约 1000 tokens。

### 问题 1：AI 重复上一轮的问题，导致用户答非所问
- **现象**：测试对话第 2 轮，AI 的回复与第 1 轮一字不差（都在问「海报用在哪儿」），用户随后回答的是别的信息，对话错位。
- **原因判断**：每轮只把对话文本传给模型，模型不清楚「已经掌握了什么、还缺什么」，容易照抄历史回复。
- **改动**：① 每轮把上一轮整理好的需求单作为状态传回给模型；② 规则中明确「每轮必须针对仍缺失的信息提新问题，禁止重复」；③ 用户答非所问时，先把回答填进对应字段再继续问。
- **效果**：同一段 6 轮测试对话中，重复提问从 1 次降为 0 次。（样本仍小，待评测集验证）

### 问题 2：用户话里已有的信息没被提取
- **现象**：用户说「社团招新海报」，「用途」字段仍为空，AI 还打算再问。
- **改动**：规则中加入「先充分提取：能从用户原话直接推出的信息立即填入」。
- **效果**：首轮即填入 品类=海报、用途=社团招新宣传。

### 已知问题（待评测阶段量化）
- 用户早期提到的时间信息（如「下周」）在后续轮次中可能丢失，截止时间字段最终为空。
- 「交付物与格式」可以从「发朋友圈和公众号」推断为电子版，但模型常留空。
- 到达 6 轮上限时预算、修改次数常未问到 → 需要评估追问优先级是否合理。
