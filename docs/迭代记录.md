# 迭代记录

> 每次改动记录：发现了什么问题 → 判断原因 → 怎么改 → 效果。面试时「遇到过什么问题、怎么解决的」就从这里讲。

## v0.1（2026-11-18）第一版跑通

**功能**：模糊需求输入 → 多轮追问（≤6 轮，带快捷选项，可随时跳过）→ 实时生成结构化需求单 → 分单判断（AI 直接做 / 人机协作 / 交给真人）→ AI 初稿 → 复制需求单 / 导出对话记录。
**模型**：通义千问 qwen-plus（百炼），单轮延迟约 4.5–6.5 秒，单轮约 1000 tokens。

### 问题 1：AI 重复上一轮的问题，导致用户答非所问
- **现象**：测试对话第 2 轮，AI 的回复与第 1 轮一字不差（都在问「海报用在哪儿」），用户随后回答的是别的信息，对话错位。
- **原因判断**：每轮只把对话文本传给模型，模型不清楚「已经掌握了什么、还缺什么」，容易照抄历史回复。
- **改动**：① 每轮把上一轮整理好的需求单作为状态传回给模型；② 规则中明确「每轮必须针对仍缺失的信息提新问题，禁止重复」；③ 用户答非所问时，先把回答填进对应字段再继续问。
- **效果**：同一段 6 轮测试对话中，重复提问从 1 次降为 0 次。（样本仍小，待评测集验证）

### 问题 2：用户话里已有的信息没被提取
- **现象**：用户说「社团招新海报」，「用途」字段仍为空，AI 还打算再问。
- **改动**：规则中加入「先充分提取：能从用户原话直接推出的信息立即填入」。
- **效果**：首轮即填入 品类=海报、用途=社团招新宣传。

### 已知问题（待评测阶段量化）
- 用户早期提到的时间信息（如「下周」）在后续轮次中可能丢失，截止时间字段最终为空。
- 「交付物与格式」可以从「发朋友圈和公众号」推断为电子版，但模型常留空。
- 到达 6 轮上限时预算、修改次数常未问到 → 需要评估追问优先级是否合理。

## v0.2（2026-11-18）转向人像修图 + 视频剪辑，品类模板化

**背景**：市场验证（`docs/决策记录.md` D1–D6）后，品类从「海报 + 文案」改为「人像修图 + 视频剪辑」。

**改动**：
- 引擎与品类解耦：每个品类是一份配置（字段、追问重点、分单规则），新增品类只需加配置（`lib/categories.js`）。
- 新增**风格翻译**：把「清透感」「氛围感」等审美词翻译成服务方可执行的要求。
- 新增**报价参考**：模型只抽取参数（修图程度、张数、成片时长等），价格由确定性规则按真实帖子数据计算（`lib/pricing.js`），避免模型编造价格。
- 新增**服务边界**：拒绝 AI 换脸、造谣、学术代写；「暂不支持的品类」与「不能做」分开处理。
- 删除文案初稿功能。

**测试**（5 个场景：修图、剪辑、换脸、学术代写、logo）：

### 问题 3：风格翻译与用户的明确要求矛盾
- **现象**：用户说「要卡点」，AI 对「氛围感」的翻译却写「避免快剪卡点」。
- **改动**：规则要求翻译与用户其他要求保持一致，冲突时以用户的明确要求为准，并说明如何兼顾。
- **效果**：复测时翻译为「以慵懒 BGM 节拍为基准做轻量级节奏剪辑（非强冲击型卡点）」。

### 问题 4：分单理由照抄规则原文
- **改动**：要求理由引用这一单的具体信息。
- **效果**：复测时为「40 段竖屏素材需结构化粗剪与节奏卡点……」。

### 问题 5：「暂不支持」被当成「拒绝」
- **改动**：新增 unsupported 状态，界面分别展示「暂不支持」和「不能接」。

### 问题 6（未解决）：把 AI 自己提出的选项当成用户的回答写进需求单
- **现象**：
  - 修图场景，AI 问验收标准，用户回答的是截止时间，需求单里却出现了 AI 提议的「家人一眼认得出是我」；
  - 另一次，AI 问「集体照还是个人照」，用户没回答，需求单里写成「1 张集体毕业照」。
- **已尝试**：在规则中明确「只有用户明确选择或同意后才能写入」。**复测仍然出现**，说明仅靠 prompt 约束不住。
- **判断**：这是最危险的一类错误：需求单会被拿去验收，编造的内容会直接引发纠纷。
- **下一步**：① 在评测中把「编造率」作为核心指标量化；② 尝试结构化方案，让模型为每个字段标注来源（用户原话 / AI 建议），AI 建议的内容在界面上显示为「待确认」。

**性能**：qwen-plus 单轮延迟约 7–9 秒（比 v0.1 长，因为 prompt 包含两个品类模板），偏慢，评测阶段对比更快的模型。

## v0.2.1（2026-11-19）评测框架上线

- 搭建自动评测：真实需求原话 + 模拟用户（三种类型）+ 评委打分。方法、评测体系自身的 4 次迭代和基线结果见 `docs/评测.md`。
- 修复：模型偶尔把字段输出成数组，界面上会粘连显示，服务端统一转成字符串。
- 用例统一为 15 条（删除 1 条免费练手帖）。发现单次运行波动很大，正式基线改为跑 3 次取均值。
- 基线（3 次均值）：编造率 4.0%、添油加醋率 23.2%、召回率 67.4%；风格（33%）和验收标准（22%）是短板。
- 下一步：① 字段来源标注，解决编造；② 改进风格追问（对比式选项、问「最不能接受什么」）；③ 用评测对比改进前后的数据。

## v0.3（2026-11-19）针对风格和验收标准优化提问策略

- 风格改用对比式选项，并追问「最不能接受什么」（来自用户洞察：7/15 的修图需求用否定句表达）。
- 验收标准改用确认式：AI 草拟 2–3 条，由用户确认或修改。
- 规定轮次规划；剪辑新增「叙事与内容重点」字段。
- AI 自报未确认字段，在需求单上标「待确认」（界面显示为橙色）。
- 剪辑价格参考补充了真实数据（30 元/分钟口播、200–300 元/条英文视频、1 万年会视频）。
- 服务边界：视频类作业按「是否考核剪辑能力」区分。
- 稳定性：模型调用加超时与重试（一次评测曾因请求无响应卡住 20 多分钟）。
- **效果**（详见 `docs/评测.md`）：风格召回 33%→53%（修图）、60%→76%（剪辑）；验收标准 22%→48%；但「需要修的地方」「BGM/字幕」下降，总召回持平。结论：提问优先级是零和的，下一步要提高每轮信息密度。

## v0.4（2026-11-19）快速选择题：提高每轮信息密度

- 前 2 轮附带最多 3 个事实型快速选择题，界面上点选即可，和主问题的回答一起发送。服务端过滤：风格、验收标准、不能改动的地方、叙事重点不允许放进快速选择题。
- 问题：剪辑编造率升到 3.9%，原因是 AI 按惯例默认「修改 2 次」。修复：禁止用惯例填字段。
- 界面问题（截图检查发现）：选中选项的文字不可见；对话气泡重复显示选择题；点主选项会丢掉已选的快速选项。均已修复。
- **效果**：总召回修图 67%→75%、剪辑 58%→65%；修图编造率 4.0%→1.9%；代价是单轮延迟约 9→14 秒。详见 `docs/评测.md`。

## v0.4.1（2026-11-19）AI 自助操作指引

- 判定为「AI 工具自助」或「AI + 真人」时，需求单下方出现「教我用 AI 工具自己做」：把需求单翻译成醒图/美图秀秀或剪映里的操作步骤，并附带对照需求单的自查项。
- 来源：调研中 5/15 的修图用户「自己修过但不满意」，以及「跟 AI 聊了 3 天才做好海报」。问题不在工具能力，而在不知道该怎么调。
- 风险控制：要求只写常见功能名，不编造菜单路径；界面注明「菜单名称以 App 实际为准」。
- 已知问题：要求不给精确参数，模型仍会给出「+15～20」这类大致范围，未经验证。后续可请修图师审核一批指引。

## v0.4.2（2026-11-19）来自真实试用的界面与交互改进

以下问题都是**在部署后的真实试用中发现的**，模拟评测测不出来：

| 发现 | 改动 |
|---|---|
| 选项文字居中，长选项难读 | 选项一律左对齐 |
| 「需要修的地方」「不能改动的地方」「验收标准」用户会同时选多个，只能单选 | 快速选择题和主问题选项都支持多选（模型判断 + 代码对这几个字段强制允许多选） |
| 「清透感」「要像本人」被标成「待确认」：模型把用户原话改写成了别的说法，自标来源又标错 | 字段值要求沿用用户原话；代码核对内容在用户原话中出现过的，不标「待确认」 |
| 对话气泡重复快速选择题的问题 | 有快速选择题时，主问题只能有一个问号，且不能涉及快速选择题的字段 |
| 页面左右留白太多 | 最大宽度 1200px → 1680px |
| 找不到「AI 分单」：结果只在对话结束后出现，且叫「建议执行方式」 | 卡片常驻显示并改名「🧭 AI 分单」，对话中先说明会判断哪三种去向 |
| **选项都不合适时没有出路** | 每组选项后增加「都不是，我自己说」「不确定，你帮我建议」；快速选择题增加「不确定」 |
| **风格选项本身也很抽象**：「舒缓电影感：慢节奏 + 呼吸感转场」和「氛围感」一样说不清 | ① 问风格时先要参考（博主 / 视频 / 照片链接），界面固定出现「📎 我有参考」按钮；② 选项必须描述看得见、听得到的效果，列出禁用的抽象词 |

**一个更深的结论**：用文字解释审美，本身就有上限。真实帖子里，用户也是靠「例图」「样片」「参考博主」「试 p」来对齐审美的（R03、R13、V06、V09）。所以下一阶段的方向是**参考图优先**：支持上传参考图 / 视频链接，并为常见风格准备示例图库，让用户「指着图选」，而不是「读着字选」。
| 助手在回复里列了验收标准的例子（✅ 列表）并提问，但下方没有对应的可点选项，用户只回答了快速选择题，主问题被跳过 | ① 规则要求选项必须放进 options；② 代码兜底：options 为空而回复里有列表时，自动把列表提取成可点选项（默认可多选），并从显示文字中去掉 |
| （截图检查时发现）用户点「直接生成」跳过了验收标准的确认，需求单里却写入了 AI 自己提议的验收标准 | 代码校验：本轮新填、内容更像 AI 这一轮的话而不像用户的话的字段，标「待确认」；用户点「直接生成」时本轮新填的字段一律标「待确认」；用户回答「可以 / 就这样」且内容来自上一轮提议的，视为已确认 |

## v0.6（2026-11-19）英文版与跨境双语需求单

- 界面中英切换（按浏览器语言默认，可手动切换，切换后重新开始对话）；字段、示例、按钮、提示全部双语。
- 英文模式：prompt 要求全部输出英文、选项避免 cinematic / aesthetic / vibe 等抽象词；「待确认」标记为「(to confirm)」；代码校验在英文下改用词级重叠，并识别 yes / sure / sounds good 等确认语。
- 报价、自助指引支持英文（工具换成 Facetune / Lightroom、CapCut）。
- 新增 `/api/bilingual`：英文需求单 → 中文版需求单 + 审美词解释 + 跨文化提示；可一键复制中英双语版本。
- 测试：英文完整对话输出中文字符 0 个；用户没回答的「叙事重点」在英文模式下同样保持「待确认」。
- 新增英文项目介绍页 `/en/case`；中文页增加「出海延伸」一节。
