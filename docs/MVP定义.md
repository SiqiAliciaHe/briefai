# MVP 定义：BriefAI 需求助手

> 版本 v0.2 ｜ 2026-11-18 ｜ 方向由市场验证调整，详见 `docs/决策记录.md`

## 1. 一句话定位

把需求方「修得好看点」「剪得有氛围感」这类模糊、主观的要求，变成修图师、剪辑师**能照着做、能照着验收**的需求单，减少返工和纠纷。

## 2. 为什么是这个方向（来自真实数据）

- 2022 年参与「交我活」（校园技能交易平台）运营。2026 年回头验证：**AI 能做好的部分（商业文案、简单海报），找人做的需求已基本消失**（D1、D2）。
- 剩下的人工需求集中在**主观、难描述**的视觉服务：人像修图、视频剪辑（D3、D4）。核心痛点是需求方说不清、双方预期对不上：
  - 修图纠纷：「10 元精修，修成这样你收我 10？？？」
  - 剪辑师自己写「下单须知」，要求客户提供素材、风格、参考视频、BGM 等。**市场已经自发长出了需求单**
- 不论最终由真人还是 AI 工具执行，都要先把「要什么」说清楚。

## 3. 目标用户与品类

| | 说明 |
|---|---|
| 用户 | 需求方：学生、个人（毕业照、生活照、旅行 Vlog、课程作业视频等） |
| 首发品类 | 人像修图、视频剪辑（品类模板化，logo / PPT 等可通过配置扩展） |
| 业务锚点 | 小红书、闲鱼上的修图/剪辑接单交易；美图、醒图、剪映等工具的「用户说不清要什么」问题 |

## 4. 核心流程

```
模糊需求 → 识别品类 / 服务边界判断（拒绝 AI 换脸、造谣、学术代写）
        → 多轮追问（≤6 轮，可跳过），优先问最容易引发纠纷的信息
        → 需求单（含「不能改动的地方」「验收标准」）
        → 风格翻译：「清透感」「氛围感」→ 可执行要求
        → 报价参考：模型只抽取参数，价格由规则计算（不让模型直接报价）
        → 执行建议：AI 工具自助 / AI 处理 + 真人精修 / 交给真人
        → 复制需求单发给服务方；导出对话记录用于实验
```

## 5. 范围

**做：** 以上流程；两个品类模板；服务边界；对话日志导出
**不做：** 修图或剪辑本身、图片/视频上传、登录、支付、服务方匹配

## 6. 指标体系

| 类型 | 指标 | 怎么测 |
|---|---|---|
| 北极星 | **首次交付通过率**（服务方第一次交付即被接受） | 真实交易实验 |
| 业务过程 | 沟通轮次、返工次数、纠纷/不满意次数 | 真实交易实验（有/无需求单对比） |
| AI 效果 | 关键信息召回率、**编造率**（把未确认的信息写进需求单）、风格翻译可执行性、边界判断准确率 | 评测集 + 模拟用户 + 人工复核 |
| 护栏 | 中途放弃率、平均追问轮次、单轮延迟 | 日志 |
| 成本 | 每单 token 成本 | 日志 |

## 7. 验证计划

1. **真实交易实验**：招募 10–15 个真实修图/剪辑需求，对接会修图、剪辑的同学；一半先用 BriefAI 生成需求单，一半直接沟通，对比返工和满意度。
2. **效果评测**：30–50 条真实需求原话 + 模拟用户，自动统计 AI 效果指标，人工抽检校准。
3. **模型选型**：通义千问 Plus / Max 等在效果、成本、延迟上的对比。

## 8. 风险与待回答问题

- 用户为什么不直接用醒图、剪映？→ 简单需求确实应该直接用（产品会建议「AI 工具自助」）；复杂、主观的需求才需要澄清和真人。
- 追问太多用户会烦 → 轮次上限、可跳过、护栏指标。
- 样本量小 → 定位为方向验证，并给出正式 A/B 实验方案。
