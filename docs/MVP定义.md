# MVP 定义：AI 需求助手（暂定名 BriefAI）

> 版本 v0.1 ｜ 2026-10-31 ｜ 状态：草案，待确认

## 1. 一句话定位

面向**闲鱼技能服务类目**的 AI 需求助手：把需求方一句模糊的话，变成技能方拿到就能开工的**需求单**，并判断这单该 **AI 直接做 / 人机协作 / 交给真人**。

## 2. 背景与洞察

- 2022 年我参与「交我活」（校园技能零售平台）运营，发现交易中最大的效率损耗是：**需求方说不清自己要什么** → 来回沟通、反复返工、纠纷。
- 2026 年，AIGC 已能完成大量「周期短、要求低、单价低」的活儿（文案、简单海报）。技能交易平台的角色正从「撮合人」变为「**为任务选择最合适的执行方**」。
- 需求澄清是这条链路里 AI 最能发挥、也最容易被衡量的环节。

## 3. 目标用户与场景

| | 说明 |
|---|---|
| 主要用户 | 需求方：学生社团/学生会、个人卖家、小商家 |
| 典型场景 | 「下周社团招新，帮我做个海报，要好看点」 |
| 品类（MVP 只做 2 个） | 平面设计（海报）、文案（推文/活动文案/标题） |
| 业务锚点 | 闲鱼「技能服务」类目：发布需求 / 与卖家沟通前 |

## 4. 核心流程

```
用户输入模糊需求
   ↓
AI 多轮追问（≤ 6 轮，可随时跳过）
   ↓
生成结构化需求单：用途 / 交付物 / 尺寸规格 / 风格参考 / 文字内容 / 截止时间 / 预算 / 修改次数 / 验收标准
   ↓
查询报价参考（工具：真实采集的闲鱼报价表）→ 给出合理价格区间
   ↓
分单判断：
   ├─ AI 直接做（如活动文案）→ 生成初稿
   ├─ 人机协作（如海报文案+排版）→ AI 出文字/方向稿，真人精修
   └─ 交给真人（如品牌视觉）→ 输出需求单 + 报价区间，供发给技能方
```

## 5. 范围

**做：** 多轮澄清、结构化需求单、报价区间、分单判断、文案类 AI 初稿、对话日志（trace）
**不做：** 登录注册、支付、技能方入驻、图片生成、站内消息、App

## 6. 指标体系

| 类型 | 指标 | 怎么测 |
|---|---|---|
| 北极星 | **首稿通过率**（不返工即接受） | 真实交易实验 |
| 业务过程 | 需求方↔技能方沟通轮次、返工次数、成单时长 | 真实交易实验（有/无助手对比） |
| AI 效果 | 关键信息召回率、无效提问率、编造率、分单准确率 | 评测集 + 模拟用户 |
| 护栏 | 对话中途放弃率、平均追问轮次 | 日志 |
| 成本 | 每次对话 token 成本、响应延迟 | 日志 |

## 7. 验证计划

### 7.1 真实交易实验（Concierge MVP，核心）
- 招募 10–15 个真实需求（社团/同学），对接 3–5 位会设计/文案的同学
- 一半需求先经过 AI 助手生成需求单，一半直接口头沟通
- 记录：沟通轮次、返工次数、首稿通过率、双方满意度（1–5 分）
- 定位：方向性验证，非统计显著；并给出「在闲鱼上线的 A/B 实验设计」

### 7.2 效果评测（轻量）
- 30–50 条需求，每条含「完整版」与「模糊开场白」
- 模拟用户（知道完整需求、只在被问到时回答）与助手对话，自动统计第 6 节 AI 效果指标
- 抽 20–30 条人工复核，计算自动打分与人工一致率

### 7.3 模型选型（业务视角）
- 对比 2–3 个模型（如通义千问、DeepSeek、豆包）的 效果 × 成本 × 延迟，给出选型结论

## 8. 风险与待回答问题

- 用户为什么不直接用豆包？→ 澄清价值、交付有人负责、AI 做不好的部分有兜底
- 分给 AI 做会不会伤害技能方？→ 平台、技能方与需求方的利益平衡
- 追问太多用户会烦 → 轮次上限 + 可跳过 + 护栏指标
- 样本量小 → 明确定位为方向验证，附正式 A/B 方案
